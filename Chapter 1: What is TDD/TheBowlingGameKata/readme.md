#### The Bowling Game Kata and its learning philosophy:

| **Category** | **Details** |
|--------------|-------------|
| **What is a Kata?** | A memorized sequence of steps in TDD that represents a **form to be studied**, not just a solution. It conditions the mind and body to react to minute design decisions. |
| **Purpose** | To help developers **acquire “Design Sense”**—the intuitive ability to translate requirements into good design by internalizing the thought process of an expert. |
| **Core Idea** | Learn by **following an expert’s steps closely**, as if “your fingers are on top of theirs, your eyeballs right behind theirs.” |
| **Learning Approach** | - Memorize in **small sections**.<br>- Fully **master one section before moving to the next**.<br>- **Move slowly and deliberately**—do not rush.<br>- Let it **seep into your bones** over time. |
| **Sections to Memorize** | 1. **The First Test**<br>2. **The Second Test**<br>3. **The Third Test**<br>4. **The Fourth Test**<br>5. **The Fifth Test** |
| **Additional Section** | **“A Quick Design Session”** – Included for demonstrations, but **not part of the core “Design Sense” kata**. |
| **Why This Works** | Repetition trains the mind to **recognize patterns, refactor with confidence, and make design decisions instinctively**—similar to muscle memory in martial arts katas. |
| **Key Takeaway** | The value is in **the process, not the final code**. By internalizing the tiny steps, you develop the reflexes and intuition of an experienced designer. |

- Practice each section in sequence, following the **Three Laws of TDD** strictly. Focus on the **micro-decisions**—why a test is written a certain way, why a refactoring happens when it does—until the flow becomes second nature.
